## Root-cause verification

The guest reported:

```text
uname -m: arm64
arch: arm64
brew --prefix: /usr/local
/opt/homebrew: absent
portable Ruby executable: Mach-O 64-bit executable x86_64
```

The downloaded bottle's SHA-256 was `c90d3891dc3805de531cd262bc8f17382f499db0eb9185d76b8785ec93753fac`, matching the artifact identifier Homebrew requested. This is not an unverified damaged-download hypothesis.

The fetched Homebrew `Library/Homebrew/cmd/vendor-install.sh` explicitly states that `/usr/local/bin/brew` on an ARM Mac is treated as an x86_64 installation and selects x86_64 portable Ruby. This confirms the wrong-prefix chain already identified in [the audit](dotfiles-audit.md), rather than a generic unsupported-guest error.

A minimal second invocation of `/usr/local/bin/brew update` reproduced the same error and exit 1 using the cached bottle. Installing Rosetta would mask the incorrect architecture choice rather than repair this native Apple Silicon bootstrap path, so it was not installed.
