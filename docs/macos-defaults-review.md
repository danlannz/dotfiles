# Stored macOS preference review

Read-only discovery used to select additional defaults. The user approved **candidates 1–6**, in addition to the input/Dock baseline, for seed-only normal bootstrap. Candidate 7 is not selected. The [implementation and verification contract](macos-defaults.md) is now in place; no host or live guest application preferences were applied.

## Evidence and limitations

- Queried an explicit allowlist of **94** Dock, Finder, input, UI, trackpad, screenshot and desktop-services keys. **35** have stored host values; **59** are absent on both machines; no queries reported unknown errors.
- Host: macOS **15.7.9**. Comparison: the already-running, provisioned fresh-desktop guest on **15.6.1**, not the protected pristine baseline. No VM was started/stopped and the protected baseline remained stopped.
- Queries used native `defaults read` only. No whole preference domains, account records, recent-file history, wallpaper paths, desktop contents, credentials or arbitrary application settings were exported.
- Private allowlist/results: `~/Library/Caches/dotfiles-vm/defaults-review-20261112/` (`inspect.sh`, `host.tsv`, `guest.tsv`, `comparison.json`).
- **Stored does not mean customized. Absent does not mean disabled.** Applications can register runtime defaults that this command does not reveal. A stored value can also have been generated by macOS rather than deliberately chosen.
- This is not a complete settings diff: per-device/ByHost values, managed policies, per-folder Finder views and arbitrary app preferences are outside this inspection. Virtual hardware and different OS patch levels also limit comparison.
- Dock's bundled `Resources/default.plist` does not supply the reviewed preference keys, so it was not treated as a factory-value reference.

### Already approved baseline values

The user confirmed Dock auto-hide, mouse scaling `2`, key repeat `1` and initial repeat delay `25`, with **seed missing values only** behavior. Simulator touch indicators were already the sole tracked `.macos` preference. See the [task contract](macos-defaults.md).

### Stored choices not automatically treated as customizations

- Dark appearance is stored on both machines.
- Finder status bar is stored as off on the host; lack of a guest value does not establish a difference.
- Spelling correction, capitalization, period substitution, smart quotes, smart dashes and text completion are stored as enabled on the host. Capitalization and period substitution are also explicitly enabled in the guest; the other guest keys are absent. These are not sufficient evidence of deliberate customization.
- External/removable disk visibility, the inspected trackpad gesture values, double-click minimization setting and stored bottom-right hot-corner code match the guest.
- No explicit trackpad scaling, scrolling-direction override, screenshot format/shadow override, Dock animation override, or reduce-motion/reduce-transparency override was found in the queried keys. This does not prove the effective behavior of those features.

## Selection policy

The user reviewed and selected candidates 1–6 before expanding the authoritative implementation inventory. Do not import a whole domain or copy all stored values into the repository. Preserve existing values, including false/zero; a stored OS-created default is still preserved. No restarts, application termination, Accessibility changes, device tuning or host rollout are part of this review.
